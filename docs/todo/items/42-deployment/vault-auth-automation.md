# 배포 Vault 인증 자동화

- **서비스**: GitHub Actions, Vault
- **우선순위**: 🟡 낮음
- **현재 상태**: 읽기·쓰기 토큰을 GitHub Environment Secret으로 주입하며 만료 알림·교체 자동화는 구현하지 않았다

## 문제

현재 배포는 운영자가 발급한 Vault 토큰을 사용한다. 최초 토큰 등록, 최소 권한 정책 설정,
만료 전 수동 교체와 복구 자료 준비는 [필수 운영 절차](../../../deployment.md)에서 수행한다.
이 항목은 그 절차를 자동화하는 후속 개선이며 최초 배포의 선행 조건이 아니다.

## 할 일

- GitHub Actions OIDC를 통한 Vault 단기 인증 도입 가능성을 확인한다.
- 저장소·브랜치·Environment별 인증 범위와 배포 읽기·설정 쓰기 권한 분리를 설계한다.
- 단기 인증을 사용할 수 없는 환경의 토큰 만료 알림·교체 자동화 방식을 정한다.
- 기존 토큰을 폐기하기 전에 새 인증으로 전환할 순서와 복구 경로를 정한다.

## 검증

- 선택한 인증 방식의 저장소·브랜치·Environment 제한과 최소 권한 범위를 검토한다.
- 만료·폐기 시 운영자가 실패 원인을 확인하고 자격 증명을 교체할 수 있는지 확인한다.

## 완료 조건

- 배포 토큰의 유효 기간과 교체 시점을 자동으로 관리한다.
- 배포 읽기와 설정 쓰기 권한이 분리되어 있고 기존 운영 복구 경로를 유지한다.
