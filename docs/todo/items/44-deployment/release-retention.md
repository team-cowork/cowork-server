# 실행 중 릴리스를 보존하는 디스크 정리

- **서비스**: 모든 배포 VM
- **우선순위**: 🟠 중간
- **현재 상태**: SHA별 소스·이미지·설정 snapshot의 자동 정리 정책이 없다.

## 문제

릴리스가 누적되지만 날짜만으로 오래된 경로를 삭제하면 bind mount된 설정이나 복구 자료를 잃을 수 있다.
소스·설정·이미지의 실제 참조와 배포 잠금을 함께 고려해야 한다.

## 할 일

- 정상 릴리스의 보존 수·기간과 수동 복구 범위를 정한다.
- 실행·중지 컨테이너의 mount·이미지 및 `*-previous`·`*-candidate` 참조를 삭제 대상에서 제외한다.
- 배포 잠금과 충돌하지 않는 미리보기·명시적 적용 명령을 구현한다.
- 릴리스·settings snapshot·생성한 Prometheus 설정·미사용 이미지에 같은 참조 정책을 적용한다.
- 디스크 부족을 사전에 식별할 지표를 준비한다.

## 검증

- 실제 VM의 참조 목록과 삭제 미리보기를 대조한다.
- 현재 스택과 복구용 자료가 삭제 대상에서 제외되는지 수동 확인한다.

## 완료 조건

- 반복 정리 뒤에도 실행·복구에 필요한 자료가 보존되어 있다.
- 적용 전에 삭제 대상을 확인할 수 있고 디스크 부족을 사전에 식별할 수 있다.
