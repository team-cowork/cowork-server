# 실행 중 릴리스를 보존하는 디스크 정리

- **서비스**: 모든 배포 VM
- **우선순위**: 🟠 중간
- **현재 상태**: SHA별 소스 묶음과 이미지가 누적되며 자동 정리 정책은 없다

## 문제

배포기는 `~/.local/share/cowork/releases/<sha>`와 Docker 이미지를 보존한다.
VM별 소스·이미지 정리 기준이 없어 장기 운영 중 디스크 사용량이 계속 늘 수 있다.
모니터링·Vault·Alloy는 릴리스의 파일을 bind mount하므로 오래된 디렉터리를 날짜만으로
삭제하면 재기동에 필요한 설정을 잃을 수 있다.

## 할 일

- VM별 디스크 사용량, 유지할 정상 릴리스 수·기간, 수동 복구에 필요한 보존 범위를 정한다.
- 실행·중지 상태 컨테이너의 bind mount와 복구용 이미지 참조를 수집해 정리 제외 목록을 만든다.
- 배포 잠금과 충돌하지 않는 정리 명령을 구현하고 삭제 대상 미리보기와 명시적 적용을 제공한다.
- 소스 묶음, `~/.local/state/cowork/settings/<target>`의 파일 시크릿·생성된 Prometheus 설정, 사용하지 않는 이미지의 보존 정책을 함께 적용한다.
- 디스크 부족을 사전에 알리는 운영 지표를 준비한다.

## 검증

- 실제 VM의 참조 목록과 정리 미리보기를 대조한다.
- 현재 실행 중인 스택, `*-previous`·`*-candidate`, 복구용 릴리스가 삭제 대상에서 제외되는지 확인한다.

## 완료 조건

- 디스크 정리를 반복해도 실행 중인 설정과 복구에 필요한 릴리스가 보존된다.
- 운영자가 정리 대상을 적용 전에 확인할 수 있고 디스크 부족을 사전에 식별할 수 있다.
