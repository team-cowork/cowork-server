# Config Server 접근 보호

- **서비스**: cowork-config, 인프라, 모든 Config/Eureka Client
- **우선순위**: 🔴 높음
- **현재 상태**: 인증·서비스별 권한·TLS·방화벽 배포 코드가 구현되어 있으며 실제 운영 전환은 아직 검증하지 않았다.

## 문제

저장소에 접근 보호가 구현되어 있으나 운영 계정·인증서·Vault 토큰 발급과 서비스별 시크릿 이동을
수행했는지는 확인하지 않았다. 구현만으로 현재 운영의 설정 조회와 외부망 차단을 보장할 수 없다.

Config와 Eureka는 같은 포트를 사용한다. 전환 중 정상 클라이언트의 조회·등록을 유지하면서 다른
서비스의 설정과 비허용 네트워크 접근이 차단되는지 확인한다. 절차는
[Config Server 접근 보호 운영](../../../config-server-access.md)을 따른다.

## 할 일

- 운영 서비스별 계정·인증서·전용 Vault 토큰을 준비하고 배포 문서의 bootstrap 참조를 갱신한다.
- 공통 Vault 값 중 필요한 키만 수신 서비스 경로로 이동한다.
- maintenance window에서 Config → 앱·monitoring 순서로 배포한다.
- 클라우드 보안 그룹과 Docker 방화벽의 허용 peer를 대조하고 Docker 재시작 후 적용 경로도 확인한다.
- 계정·인증서·토큰 교체와 복구 자료를 준비하고 실제 조회 빈도에 맞춰 감사 로그 알림을 설정한다.

## 검증

- 운영 환경에서 자기 설정 조회·Eureka 등록·heartbeat·metrics 수집을 수동 확인한다.
- 미인증·다른 서비스·다른 프로파일 조회 거부와 비허용 네트워크 연결 차단을 확인한다.
- 모든 런타임의 인증서 체인·호스트 검증과 기동 결과를 기록한다.
- 감사 로그와 확인 자료에 비밀번호·토큰·Vault 응답값이 남지 않았는지 확인한다.

## 완료 조건

- 모든 운영 Config/Eureka Client가 자기 계정과 검증된 HTTPS로 조회·등록한다.
- 권한 밖 설정 조회와 비허용 네트워크 접근이 차단되어 있다.
- 최초 전환·교체·복구의 운영 확인 결과가 기록되어 있다.
