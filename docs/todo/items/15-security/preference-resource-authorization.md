# Preference 리소스별 권한 검증

- **서비스**: cowork-preference, cowork-gateway
- **우선순위**: 🔴 높음
- **현재 상태**: 프로젝트·채널 설정과 역할의 인가, 계정별 알림의 채널 멤버십 검증이 남아 있다.

## 문제

프로젝트·채널 설정과 역할에 리소스별 인가가 없어 인증된 사용자가 ID를 바꿔 다른 리소스를 조작할 수 있다.
계정별 채널 알림도 본인 확인만으로는 해당 채널의 접근 권한을 보장하지 못한다.

필요한 멤버십은 로컬 Kafka projection으로 보강한다. 요청마다 다른 서비스에 내부 HTTP로 조회하지 않는다.
기존 계정·팀 guard는 유지한다.

## 남은 권한 정책

| 범위 | 조회 | 수정 |
|---|---|---|
| 계정별 채널 알림 | 본인과 유효한 채널 멤버십 | 동일 |
| 프로젝트 설정 | 프로젝트 멤버 | 설정 관리 권한 |
| 채널 설정 | 채널 멤버 | 채널 설정 관리 권한 |
| 프로젝트 역할 | 프로젝트 멤버 | 프로젝트 역할 관리 권한 |

계정 설정의 운영 예외 허용 여부·주체·조회 및 수정 범위와 각 리소스의 세부 역할은 소유 서비스 계약에 맞춰 확정한다.
미확정 운영 예외는 거부한다. 현재 본인 확인을 전역 `ADMIN`이라는 이유만으로 우회하지 않는다.

## 할 일

- `project.member.event.v2`·`channel.member.event.v2`의 consumer·projection·마이그레이션을 추가한다.
- 검증한 `X-User-Id`·`X-User-Role` 요청자 컨텍스트와 리소스별 guard를 나머지 handler·service에 적용한다.
- projection 미준비·권한 없음·리소스 없음의 응답을 구분하고 시크릿 없는 감사 로그를 남긴다.

## 검증

- ID 변조, 일반 멤버·관리자·운영 예외의 허용·거부 정책을 권한 서비스 단위 테스트로 확인한다.
- 공개 라우트의 요청자 전달·guard 호출은 정적으로, 삭제·권한 회수 반영은 운영 지표·데이터로 확인한다.

## 완료 조건

- 모든 공개 Preference API가 리소스별 권한을 확인하며 ID 변조로 타인의 설정·역할을 읽거나 변경할 수 없다.
- 핵심 허용·거부 정책이 단위 테스트로 보호되어 있다.
