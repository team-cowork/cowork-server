# CI 워크플로 변경 시 서비스 검사 조건 통일

- **서비스**: Stage CI, Prod CI, 전체 서비스 모듈
- **우선순위**: 🟡 낮음
- **현재 상태**: CI 워크플로 파일 변경을 일반 서비스 검사 대상으로 감지하는 조건이 `cowork-chat`과 `cowork-promotion`에만 적용되어 있다.

## 문제

`.github/workflows/cowork-stage-ci.yml`과 `.github/workflows/cowork-prod-ci.yml`의 `Detect Changed Services` 단계는 `cowork-chat`과 `cowork-promotion` 필터에 각 CI 워크플로 경로를 포함한다. 다른 서비스 필터에는 같은 조건이 없으며, Gradle 서비스는 별도의 `gradle-shared` 조건으로 공통 빌드 설정 변경을 감지한다.

chat의 워크플로 경로 조건은 Node 린트 단계를 추가한 커밋 `1df2a83d`에서 도입되었고, promotion의 조건은 XO 린트 적용을 확대한 커밋 `7963e079`에서 추가되었다. CI 절차 변경 시 해당 검사를 실행한다는 목적은 타당하지만, 현재 조건은 워크플로에서 수정한 단계와 관계없이 두 Node 모듈만 선택한다. 다른 언어의 검사 절차만 수정하면 해당 서비스의 일반 검사 대신 Node 모듈 검사가 선택될 수 있다.

`deploy/images/build-matrix.py`는 두 CI 워크플로와 `.github/workflows/cowork-prod-cd.yml` 변경을 이미지 카탈로그 전체의 빌드 입력 변경으로 처리한다. 이미지 빌드는 일반 린트·단위 테스트 검사를 대신하지 않으며, `cowork-promotion`은 `deploy/images/catalog.json`에 등록되어 있지 않다. 서비스 검사와 이미지 빌드의 대상 선택은 목적에 맞게 구분하여 정리한다. 이번 점검은 소스와 커밋 이력으로 확인했으며 실제 GitHub Actions 실행은 아직 검증하지 않았다.

## 변경 감지 정책

| 변경 범위 | 정리 방향 |
|-----------|-----------|
| 각 CI 워크플로 파일 | 해당 워크플로의 전체 서비스 일반 검사 대상으로 선택하는 공통 조건을 적용한다. |
| 개별 모듈 경로 | 기존 모듈별 선택 조건을 유지한다. |
| 공통 Gradle 입력 | 기존 `gradle-shared` 조건을 유지한다. |
| `docs/todo/**` | promotion의 실제 빌드 입력이므로 promotion 선택 조건을 유지한다. |
| 이미지·CD 입력 | 일반 검사와 목적이 다르므로 기존 이미지 빌드·배포 선택 조건에 미치는 영향을 확인한다. |

`cowork-promotion/scripts/lib/build-config.mjs`는 저장소의 `docs/todo/`를 기본 입력으로 사용한다. 따라서 이 경로 조건은 CI 워크플로 경로의 중복 정리와 별개로 유지한다.

## 할 일

- Stage·Prod CI에 각자의 워크플로 파일 변경을 감지하는 공통 조건을 추가한다.
- 공통 조건을 일반 서비스 검사 매트릭스의 모든 모듈에 적용한다.
- chat과 promotion에 중복된 워크플로 경로 조건을 공통 조건으로 옮긴다.
- 모듈별 경로, 공통 Gradle 입력, promotion의 문서 입력 조건을 보존한다.
- `workflow_dispatch`의 전체 모듈 선택과 이미지·CD 매트릭스 선택에 미치는 영향을 확인한다.

## 검증

- YAML 문법과 필터 출력에서 서비스 매트릭스까지의 조건 연결을 정적으로 확인한다.
- 변경 경로별 예상 대상을 대조한다. 각 CI 파일만 변경하면 해당 워크플로의 전체 모듈이 선택되고, 개별 모듈만 변경하면 기존 대상이 유지되는지 확인한다.
- `docs/todo/**`만 변경하면 promotion이 선택되고, 공통 Gradle 입력만 변경하면 기존 Gradle 대상이 유지되는지 확인한다.
- 회귀·통합 테스트를 작성하거나 실행하지 않고 문법 검사와 조건 검토로 검증한다.

## 완료 조건

- Stage·Prod CI 모두 자신의 워크플로 파일 변경 시 전체 서비스의 일반 검사 대상을 선택하도록 구성되어 있다.
- 특정 서비스에만 워크플로 변경 검증이 적용되는 예외가 남아 있지 않다.
- 일반 소스 변경의 모듈별 선택과 promotion의 문서 입력 감지가 유지되어 있다.
- 일반 검사 조건 정리가 이미지 빌드·CD 배포 대상 선택을 의도치 않게 변경하지 않는다.
