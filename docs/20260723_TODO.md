### 문제

Config Server는 서비스의 데이터베이스 비밀번호, 세션 서명키, OAuth 자격 증명, MinIO 자격 증명 등 Vault에서 조회한 설정을 각 서비스에 전달한다. 여러 인스턴스에 분산 배포된 모듈이 Config Server와 Eureka에 접근할 수 있도록 호스트 포트 `8761`을 모든 네트워크 인터페이스에 공개한 상태이며, Config Server 자체에는 요청 인증이 없다. 따라서 해당 포트에 도달할 수 있는 사용자가 다른 서비스의 설정을 조회할 수 있다.

### 할 일

- Config Client와 Config Server 사이에 인증을 적용한다.
- 운영 환경에서는 TLS 또는 mTLS로 설정 조회 구간을 암호화한다.
- Config Server와 각 서비스에 최소 권한 자격 증명을 사용하고 서비스별 설정 조회 범위를 분리한다.
- 인증 적용 후 운영 네트워크 정책에서 허용된 배포 인스턴스만 Config Server에 접근하도록 제한한다.
- 인증되지 않은 요청과 다른 서비스 설정에 대한 접근이 거부되는지 통합 테스트를 추가한다.
- 인증 방식과 로컬·운영 환경별 접속 방법을 `docs/configuration.md`에 문서화한다.

### 완료 조건

- 인증되지 않은 Config Client 요청은 거부된다.
- 한 서비스의 자격 증명으로 다른 서비스의 설정이나 시크릿을 조회할 수 없다.
- 허용되지 않은 외부 네트워크에서는 Config Server와 Eureka 포트에 접근할 수 없다.
- 설정 조회 과정에서 시크릿이 평문 네트워크로 전송되지 않는다.
