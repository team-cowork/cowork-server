# 테스트 작성 규칙

## 범위

- 서비스의 비즈니스 규칙(권한, 검증, 상태 변경)은 단위 테스트로 확인한다.
- 컨트롤러 테스트는 standalone MockMvc로 요청 검증과 상태 코드만 확인한다. `ControllerTestSupport`를 상속한다.
- 데이터베이스나 외부 서비스가 필요한 통합 테스트는 작성하지 않는다. 쿼리는 로컬 MySQL에서 직접 확인한다.

## 작성 방법

- JUnit 5와 MockK를 쓴다.
- 테스트 이름은 백틱으로 감싼 한국어 문장으로 쓴다. 예: `` `비공개 팀은 멤버가 아니면 조회할 수 없다` ``
- 본문은 준비, 실행, 검증 순서로 빈 줄을 두어 나눈다.
- 시간이 들어가는 로직은 `Clock.fixed`를 주입해서 확인한다.
- 리포지토리 목은 `relaxed = true`로 만들되, `save`의 반환값을 쓰는 경우에는 직접 `answers { firstArg() }`로 정한다.

## 실행

```bash
./gradlew test
```

CI는 PR마다 같은 명령을 실행하며, 실패하면 테스트 리포트를 7일 동안 보관한다.
