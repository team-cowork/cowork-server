# 로그인 식별자 전환

1. 배포 전에 User와 Authorization DB를 백업합니다. Kafka에 `user.identity.command.v3`, `user.identity.result.v2`, `user.identity.result.v2-dlt` 토픽과 서비스별 ACL을 적용합니다.
2. User를 먼저 배포합니다. V25는 기존 쓰기가 끝날 때까지 기다린 뒤 DataGSM 학생 번호 열의 이름을 변경합니다. 계정별 로그인 식별자와 학생 정보를 복사하고 기존 Cowork ID를 보존합니다. 기존 명령 소비자는 기존 그룹에서 대기 중인 v2 명령을 계속 처리합니다.
3. Authorization을 배포합니다. 새 로그인은 v3 명령을 발행합니다. 기존 결과 소비자는 이전 결과를 기존 작업에 반영합니다. 새 결과 소비자는 같은 작업 ID와 결과 버전을 확인한 뒤 User가 저장한 ID, 이메일, 학생 역할을 세션에 사용합니다.
4. 기존 학생으로 로그인하여 팀 소속과 프로필이 유지되는지 확인합니다. 기존 생산자, 미발행 outbox, 소비 지연 및 미완료 작업이 모두 정리된 후 구 토픽과 열을 별도 릴리스로 삭제할 수 있습니다.

V25 이후 User 복구에는 V25를 지원하는 이미지를 사용합니다. 이전 User 이미지는 변경 전 열을 사용하므로 로그인과 학생 웹훅을 처리할 수 없습니다. 이전 스키마로 돌아가야 한다면 전환 뒤 생성된 계정과 연관 데이터까지 포함해 복구 시점을 맞춰야 합니다.
