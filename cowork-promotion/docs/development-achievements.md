# 개발 성과 페이지 기획

## 목적

제품을 처음 보는 사람에게 학생 팀이 쌓은 개발 성과를 보여준다. 메인 첫 화면에서 GitHub 버튼 옆의 ‘개발 성과 보기’를 눌러 별도 페이지 `/achievements/`로 이동한다. 기존 TODO 페이지의 진입 위치와 보조 버튼 형태를 따른다.

## 보여줄 성과

| 성과 | 표현 | 선택 이유 |
|------|------|-----------|
| 변경 라인 | 함께 만든 변화 | 여러 플랫폼을 함께 개발한 작업량을 가장 크게 보여준다. |
| 주간 최다 병합 PR | 가장 뜨거웠던 한 주 | 전체 기록에서 한 주에 가장 많은 변경을 반영한 성과를 보여준다. |
| 기여자 | 함께한 컨트리뷰터 | 저장소 사이에 겹치는 사람을 한 번만 센다. |
| LLM 생성 코드 | 98% | 사용자가 제공한 수치다. GitHub 자동 집계와 분리하고 화면에는 별도 추정 라벨을 붙이지 않는다. |
| 커밋 | 한 번의 커밋, 한 걸음의 전진 | 저장소 구분 없이 전체 기간의 개발 기록을 보여준다. |

추가 후보인 배포 횟수, 테스트 커버리지, 응답 속도는 비교 가능한 측정 자료가 준비된 뒤 검토한다. 이번 페이지에는 넣지 않는다.

## 화면 방향

- 메인 페이지처럼 화면을 고정한 채 스크롤 진행에 따라 장면이 바뀌는 풀 페이지 인터랙션을 사용한다. 성과 카드를 나열하는 대시보드 구성은 사용하지 않는다.
- 기존 흰색·본문·브랜드 색을 유지하며 GitHub diff의 초록 `#1a7f37`·`#dafbe1`, 빨강 `#cf222e`·`#ffebe9`로 추가와 삭제를 구분한다.
- 기존 Inter와 시스템 한글 글꼴을 재사용한다. 숫자는 자릿수를 맞추고 화면마다 하나의 성과에 집중한다.
- 변경 라인과 diff → 주간 최다 PR → 기여자와 프로필 → AI 코드 모자이크 → 커밋 그래프 순서로 다섯 장면을 전개한다.
- PR 장면은 선택된 최고 기록 한 주의 수치와 그 수만큼의 토큰에 집중한다. 다른 주차의 수치·날짜·비교 그래프는 표시하지 않는다.
- 헤더에는 브랜드와 GitHub 링크를 유지하고, 개발 성과 진입은 메인 첫 화면의 보조 버튼으로 제공한다. 작은 화면에서는 기존 버튼 컨테이너가 줄바꿈을 처리한다.
- 숫자마다 출처나 설명을 붙이지 않는다. 집계 기준 패널, 기간 강조, 저장소별 분할, 추정 라벨도 표시하지 않는다.
- 메인의 스크롤 위치 계산을 재사용하고 단계 버튼으로 원하는 장면으로 이동할 수 있게 한다. 휠·터치 스크롤을 가로채지 않는다.
- JavaScript를 끄거나 모션 감소를 설정하면 모든 장면을 일반적인 세로 흐름으로 읽을 수 있게 한다.

## 수치의 의미

초기 스냅샷 기간은 한국 시간 2026년 4월 26일 00:00 이상부터 10월 26일 00:00 미만까지다. 수집할 때 공개된 `team-cowork` 소유 저장소 전체를 대상으로 하며 포크는 제외하고 보관된 저장소는 포함한다.

변경 라인은 각 저장소 기본 브랜치의 고정된 커밋에서 도달할 수 있는 이력 중, 기간 내 비병합 커밋의 추가·삭제 라인을 합친 누적 작업량이다. 같은 라인을 여러 번 고치면 그만큼 누적된다. 문서·잠금 파일·생성 코드도 포함하므로 현재 소스 코드 크기나 기능 수를 뜻하지 않는다.

주간 최다 PR은 수집 시점 이전의 전체 병합 이력을 한국 시간 월요일 00:00부터 다음 월요일 00:00까지 나누어 집계한다. `develop`, `dev`, `development`에서 `main`, `master`로 보내는 릴리스 PR은 중복으로 세지 않도록 제외한다. 봇이 대신 개설한 작업 PR은 포함하며, 최다 건수가 같은 주가 여러 개면 최근 주를 선택한다. 초기 최고치는 2026년 10월 12일 시작 주의 65개다. 화면은 이 65개만 시각화한다.

커밋은 각 저장소의 고정된 기본 브랜치 HEAD에서 도달 가능한 전체 GitHub `history.totalCount`를 합산한다. 기간 제한 없이 병합·봇 커밋도 포함하며 초기 스냅샷은 4,878개다. 기존 3,138개는 기간 내 비병합 커밋 수였으므로 화면에는 쓰지 않고 `periodCommits` 메타데이터로만 남긴다.

기여자는 해당 비병합 커밋 작성자와 연결된 GitHub 계정 ID를 기준으로 저장소 전체에서 중복을 제거한다. 봇과 알려진 AI 계정은 제외한다. GitHub 계정과 연결되지 않은 작성자는 별도 메타데이터로 기록하고 표시 인원에는 합치지 않는다. 개인 이메일은 스냅샷에 저장하지 않는다.

## 갱신과 확인

빌드는 저장된 스냅샷을 사용하므로 GitHub 접근이나 인증 없이 실행할 수 있다. 페이지는 먼저 이 수치를 보여주고 `/api/achievements`에서 자동 갱신한다. 서버는 GitHub GraphQL의 모든 페이지를 수집해 완성된 결과만 반환한다. 성공 결과는 한 시간 캐시하며 동시 요청은 하나의 수집을 공유한다. 인증 미설정, 호출 제한, GitHub 오류 또는 120초 제한에 걸리면 최근 성공 결과나 기존 스냅샷을 반환하고 1분 뒤 재시도할 수 있게 한다. 브라우저 요청 실패 시 기존 HTML을 유지한다. 최초 실제 수집에 약 55초가 걸려 함수 제한은 150초, 브라우저 제한은 135초로 설정한다.

운영 환경에서는 Vercel의 서버 전용 `GITHUB_TOKEN`에 공개 저장소를 읽을 수 있는 토큰을 설정한다. 토큰은 HTML·번들·응답에 포함하지 않는다. 로컬 서버와 수집 CLI는 기존 `gh` 인증도 재사용할 수 있다. 스냅샷 자체를 갱신하려면 다음 명령을 실행한다.

```sh
cd cowork-promotion
npm run collect:achievements -- --end 2026-10-26
npm run build
```

`--end`는 한국 시간의 종료 날짜이며 해당 날짜 00:00은 포함하지 않는다. 생략하면 한국 시간의 오늘을 사용한다. 부분 수집 실패 시 이전 스냅샷을 보존한다. 수집 결과에는 기간·기본 브랜치 커밋·제외 건수를 남긴다.

집계 로직의 단위 테스트와 lint·정적 빌드를 확인한다. UI는 데스크톱과 모바일에서 직접 확인한다. 회귀·통합 테스트는 추가하거나 실행하지 않으며 기존 모듈 테스트 명령과 CI 설정은 유지한다.
