# 운영 데이터 저장소 변경 제약

설정·배포 동작은 [runtime](./runtime.py)과 [Compose](./compose.yaml)를 기준으로 한다.
실제 자원 등록은 DB VM의 `/etc/cowork/datastores-bootstrap.json`, 접근 범위는
[root 방화벽 정책](../DATASTORE-FIREWALL.md)에 있다. 일반 CD는 등록된 데이터셋을 갱신하며
최초 생성·초기화·데이터 이동을 수행하지 않는다.

## 운영자가 별도로 처리할 변경

- DB 계정의 비밀번호는 엔진 내부와 Vault에서 함께 교체한다. 초기 기동용 환경변수만 바꾸어도
  기존 MySQL·PostgreSQL·MongoDB 사용자의 비밀번호는 바뀌지 않는다.
- 엔진 major 변경이나 데이터셋 이동은 공식 업그레이드 또는 별도 재구성 절차를 준비하고 자원
  등록을 갱신한다. minor 변경도 데이터 포맷 호환성과 downgrade 제한을 확인해야 한다.
- Kafka 파티션·복제 수·기존 토픽 정책 변경은 별도 검토가 필요하다. 토픽 생성 성공은 앱의
  projection 동기화 완료를 뜻하지 않는다.

새 엔진의 첫 기동이 데이터 형식을 바꿀 수 있다. 배포 실패 시 이전 이미지를 같은 볼륨에 연결하는
것을 복원으로 간주하지 않는다. 실제 상태와 private 진단을 확인한 뒤 복구 방향을 결정한다.
같은 이름의 볼륨 교체는 등록 검사로 감지하지만, 관리자가 볼륨 내부를 지우는 행위는 감지하지 못한다.
데이터 삭제·복원은 해당 서비스의 writer와 projection 재구성을 함께 다뤄야 한다.
